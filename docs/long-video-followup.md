# 同一视频的连续追问

> 兼容路径：本页的任务、规划、对照或追问工具仅由 `node dist/legacy-research.js` 暴露；默认 `node dist/index.js` 不注册这些工具。`npm run task -- ...` 自动使用兼容入口，已有记录无需迁移。新接入由 harness 管理上下文、来源选择、比较和追问，Catalyst 提供逐来源读取及读取进度恢复。见[默认使用方式](../README.zh-CN.md)。

`follow_up_long_video_research` 从一份已保存的长视频研究提出新问题，复用已完成概览段的原始字幕或转写，再按新问题分析。每次追问创建独立记录，保留父记录及其问题、报告和版本。

## 使用方式

先通过 `analyze_long_video_url` 保存研究，再用结果中的 `session.id` 追问：

```text
follow_up_long_video_research({
  session_id: "<父记录的 session.id>",
  question: "课程中介绍的两种注意力机制分别解决什么问题？",
  mode: "language",
  timeout_seconds: 900
})
```

文字材料足够时，这条路径不下载媒体、不调用 ASR，但会调用模型重新分析文本并综合回答。旧问题的报告、相关性分数、精读焦点、Findings 和最终答案都不直接进入新问题的分析。

公式、图表或幻灯片需要实际画面时，使用多模态追问：

```text
follow_up_long_video_research({
  session_id: "<父记录的 session.id>",
  question: "请核查课程中这一注意力机制的公式，说明画面里各符号的含义；看不清处明确指出。",
  mode: "multimodal",
  max_detail_windows: 2,
  detail_window_seconds: 120,
  window_timeout_seconds: 300,
  timeout_seconds: 900
})
```

多模态追问先用已有语言材料重新确定相关片段和焦点，再获取所选精读窗口的实际音画并转写。父记录的媒体文件未保存，父精读报告和转写不作为这次新精读的缓存。新精读会产生自己的获取、ASR 和媒体分析调用。

## 输入范围

| 参数 | 规则 |
| --- | --- |
| `session_id` | 已保存的长视频记录 ID，也可以是先前追问的记录。 |
| `question` | 新问题；其分析与父问题独立。 |
| `mode` | 默认 `language`；也支持 `multimodal`。本入口不支持纯视觉追问。 |
| `max_detail_windows` | `language` 必须为 `0`，默认 `0`；`multimodal` 为 `1–4`，默认 `2`。 |
| `detail_window_seconds` | 每个精读窗口 `30–300` 秒。 |
| `url` | 可选的新访问链接；解析后的平台、内容、分 P、规范 URL 和时长必须与父记录一致。访问参数不持久保存。 |
| `timeout_seconds` | 本次共享期限，`5–1,800` 秒。 |
| `window_timeout_seconds` | 本次每段期限，`15–600` 秒。 |
| `max_download_mb` | 本次累计获取文件预算，`32–2,048` MiB；不等于网络流量硬上限。 |

追问继承父记录的来源、所选范围、概览划分、输出／转写语言及画质要求。当前 Provider、模型、接口和实际 ASR 语言配置必须兼容。要研究其他来源、范围或语言，使用新的长视频研究调用。

## 材料与覆盖

只复制父记录中 `complete` 概览段所引用、来源和原时间范围均有效的 `caption` 或 `asr` 文本。缺失、空白、外来引用、错误分 P 或重复身份不能作为可复用材料。`partial`、`failed` 和 `pending` 段的文本不被视为已完成材料。

所有新问题的概览报告都重新生成。缺少可用语言材料的窗口保持缺失，不自动下载整段来补齐，也不拿旧问题的报告替代原文。需要补全父研究时，先对父记录调用 `resume_long_video_research`，再发起新追问。

多模态追问的 **概览仍是语言覆盖**，只有实际成功处理的精读窗口属于本次音画研究。`coverage.overview_complete` 只表示所选范围的语言概览完整；`coverage.detail` 单独报告成功精读窗口。相关性判断未选出精读或精读失败时，结果及限制应明确没有成功的视觉精读，不能由语言材料声称读清公式或图表。

焦点来自新问题的语言分析，只是获取片段的导航建议。字幕／ASR 与画面的内容可能不完全对应；精读看不清时保留不确定性，不用通用知识补全。时间引用保留实际来源区间，不承诺词级、帧级或公式出现时刻的精确定位。全部 Findings 继续标记为 `unverified`。

## 子记录与恢复

结果沿用长视频结构，并增加：

| 字段 | 含义 |
| --- | --- |
| `session.id` | 本次新建的子记录 ID；与父记录不同。 |
| `follow_up.parent_session_id` | 本次使用的父记录 ID。 |
| `follow_up.parent_revision` | 读取父材料时的版本。 |
| `follow_up.reused_evidence_ids` | 复制进子记录的原始语言证据 ID。 |
| `session.reused_segments` | 本次续跑跳过的同问题已完成报告数。首次追问重新生成报告，计为 `0`。 |
| `session.processed_segments` | 本次实际尝试处理的概览和精读段数，含仅使用已有文本的新问题分析。 |

子记录首次检查点保存全部可用的概览语言材料，后续恢复不依赖父记录是否仍然存在。子记录的 Evidence、报告、覆盖和最终引用自成一份结果；相同证据 ID 只在各自结果中解释。父记录之后更新或删除，不会改写子记录已保存的材料。

超时、取消或服务重启后，使用子记录 ID 继续这个新问题：

```text
resume_long_video_research({
  session_id: "<追问结果中的 session.id>",
  timeout_seconds: 900
})
```

恢复时跳过子记录里已完成的新问题报告，只处理尚未完成段。对缺少原始语言材料的概览段仍明确报告缺失，不回退为整片下载。再次提出另一个问题，应调用 `follow_up_long_video_research` 创建下一份记录。

子记录与普通长视频记录共用[存储、锁、版本和删除规则](./research-sessions.md)：每份最多 8 MiB、总计最多 100 份，不自动清理。首次追问会占用新记录名额；不能通过改写父记录绕过容量或兼容校验。没有共享媒体缓存、后台执行或跨视频检索。

## 验收要求

实际结果单独记入[验证记录](./validation.md)。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 对已保存的课程改问一个文字问题 | 下载、ASR、媒体分析调用均为 `0`；文本分析包含新问题和原始语言证据，不包含父报告和父答案。 |
| 新问题关注父问题以外的片段 | 相关性和焦点重新计算，精读计划随新问题改变。 |
| 追问公式或图表 | 只获取新选的精读窗口；概览语言覆盖与实际音画精读分开。 |
| 父记录有缺失或失败概览 | 不把该窗口算为成功覆盖，不静默下载补齐，不把旧报告充当原始证据。 |
| 来源、分 P、时长、配置或引用不符 | 在媒体和模型工作前拒绝不安全复用，父记录保持原样。 |
| 子记录中断后删除父记录，再恢复 | 从子记录自身保存的原始文本和已完成报告恢复；引用、覆盖及来源身份仍成立。 |
| 存储失败、取消或精读失败 | 保存最近可用的独立进度，父记录不被覆盖；错误、未读范围及本次处理量保留。 |

离线调用计数和引用校验不能替代真实平台集成验收，也不能证明模型对课程、公式或 ASR 的语义准确率。
