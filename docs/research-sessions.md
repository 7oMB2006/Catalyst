# 研究记录与断点续跑

长视频研究默认保存本地进度。`resume_long_video_research` 继续同一个问题，复用已完成概览和精读，只补失败、不完整或尚未处理的分段，再综合回答。宿主负责发起续跑；工具不会自动后台继续。

## 使用方式

首次调用 `analyze_long_video_url` 返回 `session.id`。`save_session` 默认为 `true`；显式设为 `false` 时只返回本次内存结果，不创建持久记录。

```text
resume_long_video_research({
  session_id: "<原结果中的 session.id>",
  timeout_seconds: 1800,
  window_timeout_seconds: 300,
  max_download_mb: 512
})
```

| 工具 | 用途 |
| --- | --- |
| `list_research_sessions` | 列出本地记录的 ID、标题、状态、版本、更新时间和分段进度。 |
| `get_research_session({ session_id })` | 读取保存的结果、引用和覆盖情况，不请求平台或模型。 |
| `resume_long_video_research({ session_id, ... })` | 校验兼容性，补读未完成段并重新综合。 |
| `delete_research_session({ session_id })` | 显式删除指定记录；正在执行的记录不能同时删除。 |

续跑的可选覆盖参数为 `timeout_seconds`、`window_timeout_seconds`、`max_download_mb`，范围与首次长视频调用相同。每次调用有独立的期限和获取文件预算，`processing.download_bytes` 及阶段耗时仅统计本次调用。`session.reused_segments` 记录本次跳过的已完成段数，`session.processed_segments` 记录本次实际处理段数。完整结果恢复时仍可重新综合答案，不重复分段媒体分析。

小红书等来源有时需要原始分享参数才能访问。续跑可额外传入 `url`，保留新分享链接所需参数；解析后的平台内容与原记录必须一致。链接参数只用于本次获取，不落盘。未补传时使用已保存的公开来源 URL，访问失败会明确返回，原检查点继续保留。

## 复用与引用

复用以同一份记录为边界，固定原问题、模式、输出语言、画质要求、所选来源与分 P、源时长、请求时间范围和分段／精读配置。分析 Provider、模型与接口配置也必须兼容。更换这些条件需要发起新研究，不能把旧问题的相关性、焦点和结论直接用于新问题。

兼容标识包含实际生效的 ASR 语言。StepFun 按请求 `language`、`STEPFUN_ASR_LANGUAGE`、默认 `zh` 的顺序选择；显式请求语言不受默认环境语言变化影响。修复前的预览记录缺少这项兼容信息，仍可读取或删除，但续跑会明确拒绝，需要新建研究记录。

只有 `complete` 分段可以复用。恢复时核查分段身份、原时间范围、主要证据类型和引用来源；缺失、重复、跨来源或不匹配的证据拒绝复用。`failed`、`partial` 和 `pending` 段重新处理，替换该段的旧报告和证据。分段及证据 ID 在同一记录内保持稳定，最终综合只接收完成段的证据。

如果模型的 `analysis` 为空或只有空白，但 Findings 全部通过主要证据引用校验，会用这些已接受的结论、引用及限制构造非空分段报告。没有有效引用的输出仍为 `partial`；不会保存一个空报告却声称该段已完成。

概览计划在获取前保存，精读窗口在执行前完整保存。已经确定的精读窗口不会因重启而改选；概览尚未完成时，续跑可以依据补齐的概览补足尚未确定的精读计划。概览与精读的覆盖分别计算，未读范围与失败状态继续保留。全部 Findings 仍是 `unverified`，恢复成功不等于内容准确性或精确时间定位已验证。

## 保存内容与边界

默认目录是 `~/.catalyst/sessions`，可通过 `CATALYST_SESSION_DIR` 指定。目录与文件以私有权限创建；Windows 上的实际访问控制由系统管理。保存内容包括：

- 脱敏后的研究请求、来源身份、分段计划和状态。
- 已生成的字幕／转写、分段报告、引用、覆盖和结果限制。
- 已获取素材的实际质量信息，以及记录版本和更新时间。

媒体文件、临时剪辑、平台 Cookie、Provider 密钥和带签名的获取地址不持久保存。记录仍包含研究问题、源内容文字和模型报告，应放在适合保存这些内容的本地目录。已有独立调用不会自动并入记录，也没有跨问题材料缓存。

每份记录最多 8 MiB，最多保存 100 份；达到上限时明确返回存储错误，不自动删除旧记录。通过 `delete_research_session` 释放记录。没有自动过期或后台清理任务。

每次更新先写临时文件，再原子替换保存文件，并检查预期版本。同一记录的执行锁防止多个进程同时续跑、覆盖或删除。进程异常退出后，只在确认锁持有进程已经结束时回收锁；超时长短不会单独构成抢占依据。

检查点在规划后、每个分段结束后、精读计划确定后及任务结束时保存。存储失败会明确报错并停止继续执行后续付费阶段；此前成功写入的版本仍可读取。突然结束进程只能恢复最近成功写入的检查点，正在处理且未保存完成的分段可能需要重做。媒体与模型调用的外部成本不能通过本地记录实现事务回滚。

## 验收要求

这些是验收要求，实际运行结果单独记入[验证记录](./validation.md)。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 71 分钟课程中一段获取或分析失败 | 已完成段和真实引用保留，失败段未计为成功覆盖。 |
| 完成检查点后结束进程，再启动服务续跑 | 已完成段的获取、ASR 和媒体分析调用数均为 0；只处理未完成段，最终综合可重新调用。 |
| 概览成功、精读中途结束 | 保存原精读窗口，保留完成精读，只重做未完成精读，不把概览冒充精读。 |
| 一段多次失败后补读成功 | 活跃结果不被旧错误污染；证据 ID 唯一，所有最终引用均指向成功段的实际证据。 |
| 来源、分 P、时长、模式、问题或分析配置改变 | 返回不兼容错误，已有记录保持可读取，错误复用前没有媒体或模型调用。 |
| 重新解析来源时访问失败或取消 | 不用空结果覆盖原检查点；下次仍能恢复原进度。 |
| 两个进程同时续跑，或续跑时删除 | 冲突明确拒绝，文件与版本没有丢失更新。 |
| 写入失败、记录损坏或超过存储上限 | 明确返回错误，停止新增付费工作；已成功保存的版本不被半写文件替代。 |
| 包含分享参数、签名 URL 或已配置密钥的输入／输出 | 持久记录与读取结果不暴露这些访问材料，补传链接仍核对原来源身份。 |
| 调整本次期限或获取预算 | 覆盖保留，预算与处理量从本次调用计算；无自动后台续跑。 |

离线测试验证存储、恢复、调用计数和引用结构；真实平台与模型调用另行记录。两者都不能替代课程内容、公式读取或 ASR 的独立准确性核验。
