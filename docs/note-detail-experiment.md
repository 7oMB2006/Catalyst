# 流程图局部细图对照实验

2026 年 11 月 7 日，对先前误读的小红书第 24 页流程图，比较整页输入和整页加局部细图。**本轮没有达到预先设定的接入标准，正式读取工具保持原样。**

## 固定条件

- 来源：[Agent 自动化笔记](https://www.xiaohongshu.com/explore/6ae80a83000000001a0153d3)的第 24 页，原图 1080×1800，与[前次验收](./reader-quality.md)使用同一份原始字节。
- 对照组只传整页；处理组传相同整页及一份局部 PNG。裁剪框为原图像素坐标 `x=70, y=544, width=940, height=686`，覆盖完整流程图及边缘回路。只做 FFmpeg crop，没有重绘、补字、放大或重新编码为有损格式。
- 同一配置的 `step-3.7-flash`、中文问题、240 秒期限；两组使用完全相同的视觉提示和后续综合模板。问题沿用前次流程图验收，标准答案不放进请求。
- 三轮成对并行，每轮各一组；请求实际启动先后受异步调度影响，未严格控制顺序效应。每次调用独立，未根据前一轮答案调整裁剪框、问题或提示，也未重试失败样本。

原图 SHA-256 为 `8bf2fa92223c7935c079f725a5fc2246adcdcddb20753c18bb49b86169a5a3bf`，局部 PNG 为 `4380666d1edff4f9ae50f8390c6fd899ba66e0ab792514c36254d8e1f3948d91`。裁剪框事先由 Codex 看图指定，本轮没有验证自动区域定位。

实验使用实际 `researchXiaohongshuNote` 引擎，通过依赖注入固定来源与图片获取；视觉分析、后续文字综合均请求真实 Provider。它隔离了平台下载变化，不是一次新的平台获取或 MCP 端到端验收。

为表达同一页的多个视图，两组统一加入视图说明，并将原来的“每张输入图返回一项”改为“每个原始页面返回一项”。六次视觉提示的 SHA-256 相同；输出仍只允许 `image_index: 1` 对应原始第 24 页，成功结果仍为一条 `image:24:visual`。因此对照结论只适用于这份统一提示，不能直接用前次旧提示的成绩估算裁剪收益。

## 预定标准与核对方式

沿用前次的九项事实，检查判断分支、修改上限、合并顺序和日志方向。接入门槛在请求前固定为：处理组三轮都至少 7/9 完整正确、每轮优于配对整页结果、关键分支没有确定错误，且不新增原来读对关系的错误。

两个独立 Codex 上下文直接查看原图，先隐藏组别标签核对，再揭示组别。模型回答可能自行提到视图，无法保证完全盲标；这不是人类独立核验。主评分合看 `analysis` 和 Findings，另外检查第一阶段视觉观察。分为准确、错误、不完整和弃答；无法形成可校验观察的调用单列为链路失败，不混入内容弃答。

局部图最好的一次 H8 修正了多条关系，但仍把审查发现问题后的直接去向读成开草稿 PR，并把检查失败的回路读成返回审查。前者是相对配对整页新出现的错误。另一轮 K7 又回到多条关键分支倒置，局部图没有在三轮中保持收益。

N6 的视觉观察包含发布后的线上核查，最终综合却省略了该路径的一部分。该样例中，错误和遗漏同时可能发生在视觉观察与后续综合阶段。

## 资源与结论边界

原 JPEG 为 218,815 字节，局部 PNG 为 253,042 字节；处理组图片字节总量为 471,857，约为整页的 2.16 倍。模型 token 与费用不能按图片字节推算。共记录六次图像模型和四次文字综合请求，Provider 合计报告 11,150 个 prompt tokens、49,389 个 completion tokens；未将该合计拆成组别费用，也未估计金额。

局部图在一次调用中改善了读取，但有效输出率两组均为 2/3，内容收益不稳定，也出现了新增错误。因此本轮不追加正式视图处理、参数或工具。单页、每组三次只能作为这个样例的初步证据，不能证明局部裁剪对所有图表无效。

后续若再次评估，需要将输出格式稳定性、图中连线读取和最终综合遗漏分别核对。原图＋局部图的自动接入还必须处理现有每请求最多四张输入图片、19 MB 内联请求上限，以及多个视图仍属于同一原页的映射。
