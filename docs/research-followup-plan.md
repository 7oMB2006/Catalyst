# 有界补读规划

`plan_research_followup` 从已有研究结果中检查读取范围和可用证据，返回宿主可以执行的 `next_actions`。它连接候选发现、实际阅读和材料对照：宿主执行建议、收集新结果，再决定是否重新规划或对照。

规划是确定性代码，不调用模型、不访问平台、不取得媒体，也不自动执行或保存动作。它能发现结果中可计算的读取缺口，不能判断一份材料是否足以证明某个论点。

## 使用方式

传入完整研究结果，或只读引用已保存的长视频记录：

```text
plan_research_followup({
  question: "这节课怎样解释自注意力的计算过程？",
  materials: [
    { kind: "video", result: <已有视频研究的完整结果> },
    { kind: "xiaohongshu", result: <已有小红书研究的完整结果> }
  ],
  evidence_requirement: "original",
  coverage_target: "requested",
  max_actions: 3,
  max_sources: 2,
  max_rounds: 2,
  round: 1,
  attempted_action_keys: []
})
```

`materials` 接受 `video`、`note`、`xiaohongshu` 完整结果及 `{ kind: "session", session_id: "…" }`，范围为 1–3 项。不要只传最终答案、比较结论、搜索摘要或自行拼写的证据。小红书工具外层结果使用 `xiaohongshu`，取出的图文内部结果使用 `note`。读取保存记录不会更改记录或触发续跑。

| 目标参数 | 规则 |
| --- | --- |
| `question` | 本轮研究问题，3–2,000 字符。原始文本可用于新问题；旧视觉观察受原问题约束。 |
| `evidence_requirement` | `original`（默认）分别继承各材料原模式；也可明确要求 `language`、`vision` 或 `multimodal`。图文的 `text` 对应语言，`combined` 对应多模态。 |
| `coverage_target` | `requested`（默认）仅检查各材料原请求范围；`source` 明确扩大到已知完整视频／整篇笔记。扩大范围返回 `scope_extension`，不把原范围外的内容描述成原请求失败。 |
| `search_queries` | 可选的 1–3 条宿主检索词，每条 2–200 字符。只有明确提供时才规划额外的 B 站搜索；工具不从问题或比较关系生成检索词。 |
| `discovery` | 可选的已有完整 `DiscoveryResult`，用于识别搜索阻断状态，不把未读候选变成已读内容。 |

`original` 不分析问题措辞来猜测是否需要画面或全片。改变问题后，字幕、ASR、正文和 OCR 仍可作为原始文本；旧问题的视觉观察不能直接算作新问题的视觉覆盖。若原材料只研究语言，改问新问题并不会单独引入视觉补读；需要画面时显式设置证据目标。

## 缺口与可执行建议

准备层复用材料身份与证据规范化，保留原 Evidence ID、视频时间或图片页码。同一 `source_key` 的互补材料先合并实际覆盖，再计算缺口；重叠缺口合并后才切出本轮片段，避免重复建议同一读取范围。重复传入同一范围不会增加已读范围。完整源时长、页数或实际定位未知时，不能猜测定位来生成工具调用。

覆盖表示有记录的检查范围，不要求每一秒都有台词或每一页都生成 Finding。完整取得所选范围的平台字幕后，正常 cue 间隔不被当作未读；同问题下成功处理的视觉窗口／图片页也不因没有相关 Finding 而自动重看。它仍不证明字幕无漏字、逐帧看完或模型语义正确。

| `gaps.kind` | 含义与处理 |
| --- | --- |
| `coverage_gap` | 目标范围内缺少所需通道的有效读取记录，或有未完成区间／图片页。 |
| `scope_extension` | 宿主明确要求完整来源，已有请求范围之外尚未读取。 |
| `visual_question_changed` | 本轮需要视觉证据，但已有视觉观察属于另一个问题。 |
| `access_blocked` | 已有结果明确记录获取被阻断、需要认证或限流；保留原因，不建议盲目重试。 |
| `invalid_material` | 材料无法可靠解析、身份或范围不成立；保留错误，不能拼出伪定位。 |
| `requested_search` | 宿主显式提供额外搜索词，需要调用候选发现。 |

每条缺口返回所涉材料、来源、通道、时间／页码、相关证据和原因。`state` 区分 `actionable`、`blocked`、`deferred`、`previously_attempted` 和 `needs_selection`。例如缺少可靠时长或页数时，宿主须先取得范围或作出选择；没有动作不代表原始来源已被完整研究。

`next_actions` 只建议现有工具：

| 工具 | 建议用途 |
| --- | --- |
| `analyze_video_url` | 读取确定的视频时间窗口，模式对应所需语言／视觉／多模态证据。 |
| `analyze_xiaohongshu_note` | 读取确定的原始图片页范围，使用 `text`、`vision` 或 `combined`。 |
| `resume_long_video_research` | 保存记录存在可规划的覆盖缺口，且能够继续原问题与原计划。还需保持默认的原模式／原请求目标，原计划窗口不超过本次窗口上限；否则建议独立读取有界片段。换问题不能借续跑改写旧计划。 |
| `discover_bilibili_videos` | 执行宿主明确提供的检索词，返回尚未阅读、尚未检查媒体访问的候选。 |

动作包含确定性 `key`、关联 `gap_ids`、`material_ids`、来源、`tool`、该工具校验通过的 `arguments`、原因及前提。宿主应检查前提、执行选中的调用，并保留新的结构化结果；发现候选后仍须由宿主选择来源。

比较结果的 `single_source`、`not_addressed` 或没有形成共同说法，都不会自动产生补读或搜索动作。它们可能真实反映材料内容。这个入口不读取对照的模型结论来决定真假，也不将两个来源数量当作证据充分性的门槛。

搜索路径的 `blocked`、`auth_required` 或 `rate_limited` 只阻断额外搜索建议，不能推断同平台的视频媒体也无法获取。材料自身的来源访问限制约束同一 `source_key` 的获取建议。

访问错误还需来自来源解析或获取阶段；模型分析、转写、OCR 等阶段的鉴权错误不能证明平台封锁。只有类型化错误或相关能力状态能建立访问限制。部分适配器仍把 HTTP 429 记录为泛型上游错误，此时保留原诊断和 `not_checked`，不从错误文字猜测限流。

## 预算、历史与停止

| 参数 | 默认值与范围 |
| --- | --- |
| `max_actions` | 默认 `3`，范围 `1–5`；本轮返回的动作上限。 |
| `max_sources` | 默认 `2`，范围 `1–3`；本轮读取动作涉及的已知来源上限，按 `source_key` 去重。搜索候选尚未读取，不计为已研究来源。 |
| `max_rounds` / `round` | 默认总轮数 `2`（范围 `1–5`），当前轮次 `1`（范围 `1–10`）。当前轮次超过总轮数时停止。 |
| `attempted_action_keys` | 宿主显式提供已尝试动作的 64 字符小写十六进制 key，最多 `50` 项。相同动作不因上次失败而自动重试。 |
| `video_window_seconds` | 默认 `180` 秒，范围 `30–900` 秒；每个新视频动作的窗口上限。 |
| `note_pages_per_action` | 默认 `4` 页，范围 `1–10`；每个图文动作的页数上限。 |
| `action_timeout_seconds` | 默认 `240` 秒，范围 `15–600` 整数秒；写入建议工具参数的执行期限。 |
| `planning_timeout_seconds` | 默认 `10` 秒，范围 `1–30` 秒；仅约束本次材料准备与规划。 |

输入最多 2 MiB。超限明确返回错误，不静默截断材料后宣称已经检查完毕。建议动作的窗口、页码和参数继续接受目标工具的 Schema 校验。每个缺口本轮最多安排一个新读取片段；剩余范围保留，宿主取得新证据后再规划。保存记录续跑按下述原计划处理，可能涉及多个窗口。`action_timeout_seconds` 只是下次工具调用的参数，不表示规划器已经消费该执行预算。

续跑沿用已保存的窗口计划，可在期限内处理多个窗口，建议参数另设 64 MiB 本次获取预算；它不等同于一个新视频片段调用。通道范围已被成功概览覆盖时，某个精读失败不单独产生范围缺口；概览覆盖也不证明每一帧或公式已经读清。

历史和轮次由宿主维护。规划器没有后台循环、自动递增轮次、跨请求预算账本或持久执行记录。宿主执行一次动作后，应将其 `key` 加入 `attempted_action_keys`，携带更新后的材料与下一轮 `round` 再调用；只增加轮次或清空历史不会读取新证据。key 包含问题、工具、来源及实际研究参数，仅改变执行期限、窗口执行期限或获取字节预算不会绕过已尝试动作检查。

历史 key 防止相同语义动作被再次建议，不是已尝试时间／页码范围的覆盖账本。更改窗口长度或所需通道会形成新的动作，范围可能与旧动作相交；宿主应同时带回新证据，让实际覆盖参与去重。

| `stop_reason` | 含义 |
| --- | --- |
| `actions_available` | 有可执行建议；`status` 为 `planned`。 |
| `no_actionable_gaps` | 当前目标和材料中没有可生成动作的缺口；不证明问题已得到语义充分的回答。 |
| `budget_exhausted` | 没有动作可返回，且轮次或本轮预算阻止工作；已有动作时，其他超预算缺口保留为 `deferred`。 |
| `history_exhausted` | 可执行动作已出现在宿主提供的尝试历史中。 |
| `blocked` | 当前剩余缺口受访问或可靠选择条件约束。 |
| `cancelled` / `timeout` / `invalid_request` | 本次规划被取消、超时或请求无效，保留具体错误。 |

输出固定记录 `processing.model_calls: 0` 和 `executed_actions: 0`。后续由宿主执行的研究工具可能取得媒体、调用模型并产生费用；这部分不属于本次规划的使用量。

## 验收要求

真实调用与测试记录见[验证记录](./validation.md)。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 15 秒语言结果，目标保持原请求范围 | 不把视频剩余时间当作缺口。明确 `source` 后才提出范围扩展。 |
| 图文缺少某页 OCR／视觉读取 | 保留原始页码，只建议该通道的有界页范围。 |
| 同一来源的两份材料覆盖互补区间 | 先合并覆盖，不重复建议已经读取的范围。 |
| 换问题但继承视觉模式 | 旧问题视觉观察不算新问题覆盖；已有原始文字继续保留。 |
| 换问题且原材料为语言模式 | 不因换问题擅自要求画面；显式证据目标决定通道。 |
| 保存记录仍有可规划的覆盖缺口 | 满足原问题、计划与窗口预算条件时建议续跑，规划本身不修改记录。 |
| 历史 key 命中、轮次用尽或访问被阻断 | 停止或延后，返回具体原因，不隐式重复调用。 |
| 仅有 `single_source` 或材料未谈到某主题 | 不自动搜索、补读或把未涉及当作反对。 |
| 规划成功 | 输出建议仍符合目标工具参数；模型、平台、媒体执行计数均为零。 |
