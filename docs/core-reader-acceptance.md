# 核心读源验收

从仓库根目录运行 `npm ci` 后执行：

```sh
npm run test:core
```

这套离线检查复用日常测试，使用固定的来源和模型响应，无需联网或凭据。以下三个场景都通过才算读取流程通过。改动读取、引用或恢复链路后，先跑这条命令；提交前仍跑完整测试。

| 场景 | 离线通过条件 |
| --- | --- |
| YouTube 字幕回退 | 请求中文、只有英文人工字幕时，进入文字分析并把中文要点交付在主答案。证据保留英文原文、语种、原字幕时间和引用 ID；原音语种未确认时有提示。下载器只请求元数据和字幕，模型只收到一次文字请求。 |
| B 站长视频跨进程续跑 | 编译后的默认 stdio MCP 首次读取模拟的三段视频。中间 120–240 秒失败后仅该段标为未读，首尾仍有原字幕。重启后重新解析来源，只分析中间段并重新综合，首尾两段的原文、证据 ID 和时间保持不变。单独读档没有发起新请求。 |
| 小红书图文部分可读 | 尾页 OCR 缺失时，正文和早期图片仍可分别引用，主答案标明原页，状态为 `partial`，尾页不算已处理。后续视觉批次被拒时，保留前批的原页观察；组合模式也保留已取得的 OCR。 |

图文失败用例覆盖 OCR 和视觉分析。图片下载目前按所选页整体获取；下载失败时可以保留已获得的正文，但这套验收不承诺保留已下载图片的逐页结果。

## 用真实来源复查

运行 `npm run build`，让已配置 Provider 和获取工具的 MCP 客户端通过默认 `dist/index.js` 调用下列工具。每例记录两项：**读取结果**检查状态、实际覆盖、原文定位和请求类型；**内容核对**逐条将答案和它引用的字幕、转写或原图对照。重要说法没有依据、把含糊内容说成事实，或遗漏问题要求的内容，都单独记下。平台访问失败时保留实际状态和错误，内容标为未核对。

| 真实样本和调用范围 | 提问 | 内容核对点 |
| --- | --- | --- |
| [YouTube：Me at the zoo](https://www.youtube.com/watch?v=jNQXAC9IVRw)；`analyze_video_url`，`mode: language`、`language: zh`、`start_seconds: 0`、`end_seconds: 15` | 视频讲者说自己在哪种动物面前？他说这类动物有什么特点？请只用所选时段中实际说到的话。 | 大象和长象鼻；对照原英文字幕。不要用字幕确认画面实际出现了什么。若轨道仍与样本相同，确认实际只获取元数据和英文字幕，没有媒体下载或 ASR。 |
| [B 站：BVR 介绍](https://www.bilibili.com/video/BV1dPeP6REwM/)；`analyze_long_video_url`，`mode: language`、`language: zh`、`segment_seconds: 120`、`max_segments: 2`、`max_detail_windows: 0` | 视频介绍的 BVR 是什么？它有哪些使用模式，用户怎样把它接到自己的 Agent 中？ | 用途、三种模式和部署说明。当前转写里的“这样的内容”未明确指代具体材料；如果只读到这份转写，应保留这项不确定性。真实样本检查正常读取；中间段故障由离线用例注入。 |
| [小红书：Agent 自动化笔记](https://xhslink.cn/o/Af8twEpdOVh)；`analyze_xiaohongshu_note`，`mode: text`、`language: zh`、`start_page: 1`、`end_page: 2` | 按原页分别回答。第一页作者说花了多久、分享什么？第二页说一个人通常能同时跟进几个活跃会话，以及单任务和多任务分别受什么限制？ | 第 1 页是一年和 Agent 自动化系统；第 2 页是 3–5 个活跃会话，单任务上限取决于模型能力，多任务上限取决于人的注意力。用原图核对，不把笔记正文算作某一页。 |
