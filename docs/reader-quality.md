# 来源阅读器的真实内容验收

2026 年 11 月 7 日，通过编译后的默认 stdio MCP 入口，用现有 StepFun 配置检查单来源阅读器。保留 MCP 内部的模型分析，宿主继续负责对话与多来源综合。本轮检查主答案是否回答问题、解释是否符合来源，以及覆盖说明是否准确。

所有调用设置 `language: "zh"`。视频调用分别使用 240／300 秒期限、128 MiB 获取文件额度；BVR 的单窗口期限为 120 秒，课程为 240 秒。笔记调用使用 240 秒期限。模型为 `step-3.7-flash`，下载器为已有 `yt-dlp 2026.10.26`，使用 Python 3.14；图文 combined 的 OCR 使用本机可用路径。没有添加工具、A2A、原文模式或任务编排。

由 Codex 直接查看原图逐项核对，未经人类独立复核；旧 OCR 和模型报告不作为图表事实标准。第 24 页重新从来源获取后，与既有原图的 SHA-256 相同：`8bf2fa92223c7935c079f725a5fc2246adcdcddb20753c18bb49b86169a5a3bf`。视频文字的核对仅说明结论是否得到所保存 ASR 的支持，未独立核验音频转写准确率。

## 文字主答案与范围提示的改进

长视频提示现在要求 `analysis` 自身给出受证据支持的答案，随后再简述范围和限制，不能只在 Findings 中回答。综合阶段另传入请求窗口和源时长，要求以程序计算的 `coverage.unreviewed` 描述请求范围内未读区间，保留文字、视觉和转写精度的区别。

三次 BVR 调用使用同一问题、参数及相同原始 ASR 证据；按返回顺序对原始字幕／ASR 证据数组执行 `JSON.stringify`，所得 SHA-256 均为 `1eb75f031e176335b680f4c802c6d18833d43543534ba5143a8a674c7b26cc6a`。主答案从 241 字的范围说明变为实际回答，最后一次也不再虚构未读后续视频。这是固定样例上的改进，提示没有提供标准答案。

最终仍有两处语义问题：模型把来源中含糊的部署指代具体化成“研究结果用于部署项目”；也把一个分段末端的半句，泛化成整条来源末尾被截断。前者不能仅从 ASR 确定，后者与正常结束的最后一段文字不符。本轮没有继续调到样例表面全对，不能把提示变化当作语义保证。
