## 文字主答案与范围提示的改进

长视频提示现在要求 `analysis` 自身给出受证据支持的答案，随后再简述范围和限制，不能只在 Findings 中回答。综合阶段另传入请求窗口和源时长，要求以程序计算的 `coverage.unreviewed` 描述请求范围内未读区间，保留文字、视觉和转写精度的区别。

三次 BVR 调用使用同一问题、参数及相同原始 ASR 证据；按返回顺序对原始字幕／ASR 证据数组执行 `JSON.stringify`，所得 SHA-256 均为 `1eb75f031e176335b680f4c802c6d18833d43543534ba5143a8a674c7b26cc6a`。主答案从 241 字的范围说明变为实际回答，最后一次也不再虚构未读后续视频。这是固定样例上的改进，提示没有提供标准答案。

最终仍有两处语义问题：模型把来源中含糊的部署指代具体化成“研究结果用于部署项目”；也把一个分段末端的半句，泛化成整条来源末尾被截断。前者不能仅从 ASR 确定，后者与正常结束的最后一段文字不符。本轮没有继续调到样例表面全对，不能把提示变化当作语义保证。

## 图文主答案由接受的要点组成

针对上述两次主 `analysis` 没有实答的问题，图文最终提示改为只生成一份 Findings，包含答案要点、证据 ID 和必要限制；不再要求模型另写一份 `analysis`。必要限定、范围限制与未答部分应进入相关要点的 `limitations`。没有证据支持的答案要点应留空，不能为了填满答案补写结论。

新增 `collectNoteAnswer` 复用现有 `collectFindings` 的引用检查，仅取接受的 Findings。程序按原顺序把每条 statement、证据 ID、证据自身的原页码或正文定位和逐点限制组成 `analysis`；公共 Findings 的 `verification: "unverified"` 与限制保留，共同的未核验说明在可读答案中显示一次。旧独立 `analysis` 无论为空、只有范围说明、让读者看 Findings，还是含有其他内容，都不进入图文主答案；不靠关键词判断是否回答，也不追加模型修复请求。

只有部分要点通过校验时，主答案包含接受的部分，结果仍为 `partial`。没有有效要点时 `analysis: null`、Findings 为空，保留已有证据和明确告警；非法 JSON、未引用的自由文本和已丢弃要点不会作为兜底答案。这是图文输出的兼容变化：原先只写在独立 `analysis` 里的限定不再保留，外部执行器应把必要限定放进对应要点。完整请求范围、已处理页和来源限制继续通过原有 request、processing、evidence、warnings 和 errors 字段交付；新的主答案不替代这些覆盖信息。

该处理仅用于 image note 的 `text`、`vision`、`combined`。公共 MCP 输入、输出版本和工具数量不变，确认的视频笔记仍提前路由至原视频研究；共享视频引用收集器和视频、长视频、OCR、视觉请求均未修改。已有磁盘记录不会因此重写。旧任务层的续读继续保留各次读取答案，并保留原始回执中的来源证据。
